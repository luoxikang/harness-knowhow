# PB-006: Bash/工具执行应该在哪？

## 问题

Agent 调用的 Bash、Python、npm 等命令应该在哪里执行？

## 关键维度

- 延迟（命令和结果通过网络传输的延迟）
- 隐私（用户代码是否上传到云端）
- 环境一致性（是否所有用户有相同的工具链）
- 安全性（恶意命令的影响范围）

## 参考方案

### 方案 A：云端容器

```
Bash 在云端的 Docker 容器中执行
代码需要上传到容器
```

- 优点：环境可控（统一装好 Python/Node/Go），安全边界在容器
- 缺点：代码上传延迟，大文件不可行，用户隐私担忧

### 方案 B：用户本地

```
Bash 在用户的笔记本电脑上执行
代码本来就在本地
通过 Relay（WebSocket）接收命令、回传 stdout/stderr
```

- 优点：零延迟（命令在本地跑），隐私保护，工具链用户自己配
- 缺点：需要穿透 NAT，环境不受你控制

### 方案 C：混合

```
/ws/{user}/laptop-projects → 用户笔记本
/ws/{user}/cloud-container → 云容器
/ws/{user}/ci-runner       → CI 环境
```

按路径前缀路由到不同的执行环境。

- 优点：灵活，兼顾本地和云端
- 缺点：路由逻辑复杂，用户需要知道哪个 workspace 对应哪个环境

## 关键取舍

| | 云端容器 | 用户本地 | 混合 |
|---|---|---|---|
| 延迟 | 中 | 低 | 取决于路由 |
| 隐私 | 低（代码上传） | 高 | 取决于 workspace |
| 环境可控性 | 高 | 低 | 取决于 workspace |
| 连通性要求 | 低 | 高（NAT 穿透） | 中 |
| 复杂度 | 低 | 中 | 高 |
